### 1.2 Java中重载和重写的区别是什么？（6分）

```txt
1. 重载是指发生在同一个类中，方法名必须相同，参数列表必须不同（类型、个数、顺序不同），与方法的返回值类型和访问修饰符无关；
2. 重写发生在父子类（或实现接口）中，方法名、参数列表必须完全相同；返回值类型必须小于等于父类；抛出异常必须小于等于父类；访问修饰符必须大于等于父类。
```


### 1.3 说下抽象类和接口的区别？（6分）

```txt
1. 一个类只能继承一个抽象类（单继承），但可以实现多个接口（多实现）。
2. 接口中只能有public static final修饰的常量，抽象类中可以有普通成员变量
3. 接口中的方法默认是public abstract的（JDK8之后可以有default和static具体方法）；抽象类中可以有非抽象的普通方法。
4. 抽象类中有构造器（供子类初始化时调用），接口没有构造方法
```

### 1.6 Integer缓存机制是怎么样的？（5分）

```txt
Integer类部维护了一个IntegerCache静态内部类，它默认缓存了[-128,127]之间的Integer对象。
当我们根据自动装箱原理创建该范围内的整形对象时，会直接从缓存池中返回预先创建好的对象，只有超出这个范围的数字，才会每次都new新对象。
```

### 1.7 ==和equals的区别（6分）

```txt
==对于基本数据类型，比较值是否相等；对于引用数据类型，比较的是内存地址是否相同（即是否为同一个对象）。
equals()是Object类的方法。默认情况下它的实现就是==（比较地址）。但有很多类重写了equals()方法，用于比较对象的内容（属性值）是否相等。
```

### 1.8 String、StringBuilder、StringBuffer的区别（6分）

```txt
1. String底层拿final修饰的数组构成，是不可变的；StringBuilder和StringBuffer继承自AbstractStringBuilder，是可变的。
2. String因为不可变所以线程安全；StringBuffer的大多数方法加了synchronized同步锁，是线程安全的；StringBuilder没有加锁，是非线程安全的。
3. StringBuilder性能最高，StringBuffer次之，String最低（因为String每次拼接都会生成新对象）。
```

### 1.9 String为什么设计成不可变的（6分）

```txt
1. 只有字符串不可变，才能安全地实现常量池，多引用共享同一个字符串对象，节省内存空间。
2. 不可变对象天生就是线程安全的，可以在多线程环境中自由共享
3. String作为网络连接、文件路径、反射类名等核心API参数，不可变保证了参数在传递过程中不会被恶意篡改。
4. 因为不可变，其hash值也不会变，因此String对象在创建时可以缓存hash值，非常适合作为HashMap的key。
```

### 1.13  LinkedList和ArrayList的区别?（6分）

```txt
1. ArrayList底层是动态数组，LinkedList底层是双向链表。
2. ArrayList存储结构是顺序的，可以通过下标偏移量实现快速查找（O(1)）；LinkList必须从头或尾部遍历，查询速度慢（O(n)）。
3. ArrayList在尾部插入快，但在中间或头部插入/删除时需要移动大量元素，效率低；LinkedList在已知位置进行插入/删除操作只需要修改指针，不需要移动元素，相对较快。
4. ArrayList结尾可能有预留空间；LinkedList的每个节点都需要存储数据以及前后节点的指针，单个元素占用的内存比ArrayList大。
```

### 1.14 ArrayList的扩容机制是怎么样的？（6分）
```txt
1. 开始使用无参构造器创建ArrayList时，初始是一个空数组({})，第一次调用add()方法加元素时，2. 数组才会初始化并扩容为默认容量10，之后当添加元素导致容量不足时，会触发扩容机制扩容至旧容量的1.5倍。
3. 最后底层调用Arrays.copyOf()方法，将老数组的数据复制到新数组中。
```
### 1.15 HashMap在jdk1.7和jdk1.8区别有哪些？（6分）
```txt
1. 底层数据结构的改变，1.7是数组+单向链表，1.8是数组+单向链表+红黑树
2. 1.7链表使用头插法，1.8链表改用尾插法
3. 1.7的hash运算复杂，1.8简化了hash运算（只做了一次高16位异或低16位）
4. 1.7扩容后需要重算所有元素的hash并分配位置，1.8利用巧妙的逻辑，元素要么停留在原位置，要么移动“原位置+旧容量”的位置，提升了扩容效率。
```
### 1.16 HashMap链表红黑树转换的阈值是怎么样的？（5分）
```txt
当链表长度大于8，并且整个长度大于等于64，链表才会转化为红黑树，当红黑树节点数量减少到6以下时，红黑树会退化回链表，用于解决Hash冲突的问题。
```
### 1.17 HashMap的扩容机制是怎么样的？（6分）
```txt
HashMap的默认初始容量16，默认负载因子是0.75。当HashMap中的元素超过了阈值（即容量*负载因子，默认16*0.75=12）时，就会触发扩容，每日此扩容在原理的2倍，扩容时会创建一个新的两倍大小的数组，然后遍历旧数组，将所有元素重新分配到新数组中。
```

### 3 .1 Redis为什么快？（6分）
```txt
1. Redis是NoSQL型数据库结构，且基于内存操作，这是高速的基础，并且支持RDB和AOF的持久化机制
```

### 3.3 RDB 和 AOF 两种持久化机制有什么区别？（6 分）
```txt
RDB，其COW机制保证不阻塞主进程下高效的生成快照，定期将内存中的数据状态保存为紧凑二进制文件（文件体积小），快照保存，安全性较低，宕机数据会丢失修改内容，文件恢复速度极快，性能上主要是fork（）子进程是短暂阻塞，持久化过程由子进程在后台完成，对主进程I/O影响小。
AOF，主要是操作日志，记录每次执行的写命令会追加到日志文件中（文件体积会随着时间推移持续膨胀），通过fsync策略刷盘数据安全性较高，文件恢复速度较慢，需要重新执行日志中的写命令重建数据状态，性能主要取决于刷盘频率，高并发时会给磁盘I/O带来一定压力。
```
### 3.4 Redis 缓存穿透、击穿、雪崩分别是什么现象？分别如何解决？（6 分）
```txt
缓存穿透：指的是客户端持续访问缓存和数据库中都不存在的值，解决方法：1. 在接口层加强入参校验，2. 使用布隆过滤器对热门数据表做存储在访问前做判断是否拦截，3. 使用空值缓存，4. 异步回填，对于可能存在的key，使用消息队列(RocketMQ、Kafka)异步回填缓存，结合布隆过滤器动态更新。5. 进行IP限流，对异常高频的IP或用户添加黑名单或限流，防止恶意穿透。

缓存击穿：指的是瞬间大量请求，集中访问某些Key，如果在Redis中不存在，就会访问数据库，然后压力数据库甚至宕机，解决办法：使用分布式锁 + 降级和限流 这两个操作是为了兜底出现了缓存击穿的时候 保护我们的微服务不会出现级联失败（雪崩）；预防方法：1. 多级缓存，结合本地缓存和Redis缓存，先查本地缓存，减少对Redis的压力；2. 热Key预加载，提前识别热门key（通过日志分析或监控），在系统启动或低峰时期预加载到缓存，并设置较长的过期时间或永不过期；3. 逻辑过期：不设置真实的过期时间，而是将数据存入缓存时附加一个逻辑过期字段（如过期时间戳）。查询时检查是否逻辑过期，如果过期则异步线程重建缓存，主线程返回旧数据，确保不阻塞。

缓存雪崩： 由于服务器受到外部请求高压，导致服务器内存溢出或程序错误，使得与该服务相关连的微服务出现级联失败（即雪崩）。解决方法：降级限流：集成Sentinel或Hystrix，对高并发key添加限流阈值，超出时直接返回默认值或降级响应。预防措施：1. 多级缓存与热备份：引入L1和L2多级缓存，L1设置短TTL，L2设置长TTL；或使用热备份缓存（其它Redis集群），雪崩时切换。2. 随机过期时间： 为key设置过期时间添加随机偏移（如TTL + random（0，600）秒），避免大量key同时过期；3. 预热缓存： 系统启动时预加载热门数据到缓存，或使用定时任务定期刷新即将过期的key。4. 互斥锁重建，使用分布式锁确保过期key重建时只有一个线程访问DB，其它线程等待或返回旧数据。5. 熔断与限流：集成限流组件，对整体请求限速；使用Hystrix熔断器，当DB压力大时自动降级返回默认数据。6. 提高硬件架构等级：部属Redis Cluster或Sentinel，确保Master宕机时快速故障转移；结合消息队列缓冲请求，异步处理DB查询。
```
